# INFO — 情報ハブ（TOP）

中銀・政府・規制当局・ニュースの新着、EDINET・SEC EDGAR の開示、会社ごとのニュースを 1 か所に集め、カバレッジとキーワードに当たったものを知らせる。

> **未検証**：この開発環境からは外部への通信がすべて拒否される（プロキシが 403）。解析は各形式（RSS 2.0・Atom・RSS 1.0 RDF・EDINET の JSON とコード一覧 zip・SEC の JSON）の公表された形の試験データで確かめただけ。**ユーザーの PC での初回の取得で、TOP → 5) FEEDS に ✕ と理由が出たものは URL を直す**。

## 1. 画面

コマンド `TOP`（上のキー列の 2 番目）。Bloomberg 風の番号メニューで、番号を入れて Enter（`3 <GO>`）かクリックで切り替える（数字はコマンドラインに入るので、6857 のような銘柄コードの入力は邪魔しない）。

| 番号 | 画面 | 内容 |
|---|---|---|
| 1) NEW | 新着 | すべての取得元の新着（分類・地域・語で絞り込み） |
| 2) HITS | 当たり | カバレッジの銘柄かキーワードに当たったものだけ |
| 3) FIL | 開示 | EDINET（大量保有・自己株買い・公開買付・有報・半期・臨時報告書・訂正）と SEC EDGAR。PDF は端末経由で開く |
| 4) NEWS | ニュース検索 | Google ニュースを語で検索（日本語・英語） |
| 5) FEEDS | 取得元 | 一覧・状態（✓ / ✕ と理由）・停止・自分の RSS の追加・追加前の試験 |
| 6) WORDS | キーワード | 当たりにする語（既定 21 語） |
| 7) KEYS | API キー | e-Stat・FRED・EDINET・SEC の連絡先を貼って保存（§8） |

ほかの画面との連携：

- **STK（個別銘柄）**：「ニュース・開示」欄（その銘柄の EDINET・EDGAR の開示、取得元での言及、Google ニュース）。
- **BRIEF（朝のブリーフ）**：「ニュース・開示（TOP）」欄（直近 24 時間の当たりと、直近 2 日のカバレッジの開示）。
- **ECST → SOURCES**：KEYS と同じ API キーの欄。

## 3. 当たりの判定

対象の銘柄は COV のカバレッジ（Notion 銘柄マスタ）とポートフォリオ。見出しと要約を全角・半角を揃えて（NFKC）調べる。

- **コード**は「コードとして書かれている」ときだけ当てる：`（6857）` `＜6857＞` `【6857】` `（東証プライム：6857）` `6857.T` `コード6857` `TSE:6857`、米国株は `(AAPL)` `$AAPL` `NASDAQ: AAPL`。**「6857億円」「2026年」のような数字は当てない。** 2 文字以下の英字ティッカーは `$AI` `NYSE: AI` の形だけ（「(AI)」は人工知能のことが多い）。
- **社名**は正式名と、「株式会社」「ホールディングス」「Inc.」などを除いた名前（3 文字以上）。英字の社名は単語として当てる（Meta と Metallica は別）。
- **キーワード**は大文字・小文字を区別しない。既定：利上げ、利下げ、政策金利、金融政策、為替介入、FOMC、日銀、ECB、決算、上方修正、下方修正、自社株買い、TOB、公開買付、M&A、増資、関税、rate hike、rate cut、tariff、guidance。

## 4. 通知

- 新しく取り込んだ項目がカバレッジかキーワードに当たると、画面の通知とブラウザ通知（許可した場合）を出す（websocket `info_alert`）。
- **取得元を初めて読み込んだときは通知しない**（過去の分が一度に来るため）。EDINET も同じで、初めての取得では通知せず、2 回目からカバレッジの新しい開示を知らせる。

## 5. 開示

### EDINET（金融庁）

- API v2 の書類一覧 `documents.json?date=…&type=2`。**`EDINET_API_KEY`（Subscription-Key）が必要**。EDINET の「API 利用登録」で無料で発行できる。
- 巡回のたびに今日と昨日を取り直し、直近 7 日で欠けている日を埋める。400 日より古い分は消す。
- 銘柄への結び付けは**提出者ではなく対象の会社**（大量保有報告書の提出者は投資家なので）：`subjectEdinetCode` → `issuerEdinetCode` → `secCode` の順。EDINET コード一覧（zip、cp932。7 日ごとに取り直す）で EDINET コードを証券コード 4 桁にする。
- 種類：大量保有（大量保有報告書・変更報告書）、自己株買い（自己株券買付状況報告書）、公開買付、有価証券報告書、半期・四半期、臨時報告書、訂正。取り下げられた書類は除く。
- PDF は `/api/info/edinet/{docID}/pdf` で開く（キーはサーバーの中だけで使い、画面には出さない）。

### SEC EDGAR（米国）

- **`SEC_USER_AGENT`（名前とメールアドレス）が必要**（SEC の規則で、User-Agent に連絡先を入れる）。
- カバレッジ・ポートフォリオ・ウォッチリストの米国株（`NASDAQ:` `NYSE:` など、最大 60）について、`company_tickers.json` で CIK を引き、`submissions` から 10-K・10-Q・8-K・Form 4・13D/13G・DEF 14A などを取る。1 日 1 回、0.15 秒ずつ間隔を空ける（毎秒 10 回の制限より少なく）。

## 6. 会社ごとのニュース

- Google ニュースの RSS 検索（社名、無ければティッカー。日本株は日本語、ほかは英語）。結果は 1 時間保存する。
- 公開されている RSS だが仕様が変わることがある。取れないときは STK の欄に理由が出る。

## 7. 自動更新

- 起動の 2 分後から、既定で 20 分ごと（TOP の上の欄で ON/OFF と間隔 5〜1440 分）。`TERMINAL_INFO_AUTO=0` で止める。
- 取得元は 4 本ずつ並べて取り、1 つ失敗しても残りは続ける。EDINET は毎回（2 回の問い合わせ）、EDGAR は 1 日 1 回。

## 8. API キー（KEYS）

- **TOP → 7) KEYS**（または ECST → SOURCES）に貼って「保存」すると、その PC のリポジトリ直下の `.env`（git の管理外）に書き込み、**再起動なしですぐ使える**。
- 画面には伏せ字（先頭 4 文字…末尾 4 文字）だけを出す。空にして保存すると `.env` から消す。`.env` のほかの行やコメントはそのまま残す。
- 形式を調べてから保存する：e-Stat（メールアドレスは不可。マイページの「API 機能」で発行する英数字）、FRED（英小文字と数字 32 文字）、EDINET（英数字）、SEC（名前とメールアドレス）。
- 注意：Windows の環境変数に同じ名前があると、次に起動したときはそちらが優先される（`.env` は既にある環境変数を上書きしない）。
- サーバーは 127.0.0.1 だけで待ち受けるので、ほかの PC からは読めず書き換えられない。

## 9. 保存場所

`data/info/`（`TERMINAL_DATA_DIR` の下）：

| ファイル | 中身 |
|---|---|
| `items.json` | 取得した項目（新しい 5000 件）。当たりの銘柄・キーワード付き |
| `feed_status.json` | 取得元ごとの状態（最後の取得、件数、エラー） |
| `edinet.json` / `edinet_codes.json` | 日付ごとの開示一覧 / EDINET コード → 証券コード |
| `edgar.json` | CIK の対応と銘柄ごとの開示 |
| `news_cache.json` | Google ニュースの検索結果（1 時間） |
| `state.json` | 最後の巡回、1 日 1 回の処理の日時 |
